# ระบบบันทึกรายรับ-รายจ่ายเงินสดหน้าร้าน

เว็บแอประบบบันทึกรายรับ-รายจ่ายเงินสด สำหรับหน้าร้าน ใช้งานได้จากมือถือหรือคอมพิวเตอร์เครื่องไหนก็ได้ (ข้อมูลอยู่บน Firebase แบบเรียลไทม์) มีระบบตรวจสอบและกันทุจริตในตัว

## ระบบป้องกันการทุจริตที่มีอยู่ในตัวแอป

1. **แนบหลักฐานภาพถ่ายบังคับ** — ทุกรายการต้องแนบรูปสลิป/ใบเสร็จ (และรูปเงินทอนสำหรับรายจ่าย) ก่อนบันทึกได้
2. **แยกบทบาทชัดเจน** — พนักงานบันทึกรายการ ส่วนเจ้าของ/ผู้จัดการเป็นผู้ตรวจสอบและอนุมัติ ทุกรายการเริ่มที่สถานะ "รอตรวจสอบ" เสมอ
3. **ห้ามลบถาวรโดยเด็ดขาด** — ไม่มีปุ่มลบในระบบเลย แม้แต่เจ้าของก็ลบไม่ได้ ถ้าต้องยกเลิกรายการจะใช้สถานะ "ยกเลิกรายการ" แทน ซึ่งยังคงอยู่ในระบบให้ตรวจสอบย้อนหลังได้
4. **แก้ไขได้แต่ต้องมีเหตุผลเสมอ** — การแก้ไขทุกครั้งต้องกรอกเหตุผล และระบบจะบันทึกลง "ประวัติการแก้ไข (Audit Trail)" อัตโนมัติ ว่าใครแก้ อะไร จากค่าไหนเป็นค่าไหน เมื่อไหร่ ประวัตินี้ลบไม่ได้และดูได้ในหน้ารายละเอียดของทุกรายการ
5. **พนักงานแก้รายการของตัวเองได้เฉพาะตอนที่ยังไม่ถูกตรวจสอบ** — เมื่อเจ้าของอนุมัติ/ตีกลับแล้ว พนักงานจะแก้ไขไม่ได้อีก (แก้ได้เฉพาะเจ้าของ และต้องมีเหตุผลด้วย)
6. **กฎทั้งหมดถูกบังคับที่ระดับฐานข้อมูล (Firestore Security Rules)** ไม่ใช่แค่ที่หน้าเว็บ — ต่อให้มีคนพยายามแก้โค้ดฝั่งหน้าเว็บหรือเรียก API ตรงๆ ก็ยังถูกกฎเหล่านี้บังคับอยู่ดี ดูรายละเอียดได้ในไฟล์ `firestore.rules`
7. **เวลาบันทึกใช้เวลาจากเซิร์ฟเวอร์ (serverTimestamp)** ป้องกันการตั้งนาฬิกาเครื่องปลอมวันที่
8. **ทุกรายการระบุผู้บันทึกและผู้ตรวจสอบชัดเจน** พร้อมประวัติเข้าถึงย้อนหลังได้ตลอด
9. **แยกเงินหมุนเวียนเป็นฝั่งๆ (Funds)** — เช่น หน้าร้าน / ออกส่งสินค้าและเบี้ยเลี้ยง แต่ละฝั่งมียอดตั้งต้นและยอดคงเหลือของตัวเอง แยกกันชัดเจน ไม่ปนกัน
10. **เบิกเงินสำเร็จได้ก็ต่อเมื่อ "อนุมัติ + เซ็นชื่อออนไลน์" เท่านั้น** — เจ้าของต้องลงลายเซ็นในระบบ (วาดบนหน้าจอ) ตอนกดอนุมัติทุกครั้ง ถ้ายังไม่เซ็นจะอนุมัติไม่ผ่านและพิมพ์ใบเบิกไม่ได้ กฎนี้ถูกบังคับซ้ำใน `firestore.rules` ด้วย ไม่ใช่แค่ที่หน้าเว็บ
11. **พิมพ์ใบเบิก/ใบรับเงินได้เฉพาะรายการที่อนุมัติและเซ็นแล้ว** ป้องกันการพิมพ์เอกสารมาอ้างสิทธิ์เบิกเงินก่อนได้รับอนุมัติจริง
12. **ไม่ใช้ Firebase Storage** — รูปหลักฐาน/รูปเงินทอน/ลายเซ็น ถูกบีบอัดที่เครื่องผู้ใช้แล้วเก็บเป็น base64 ลง Firestore โดยตรง

> หมายเหตุ: นี่คือแนวป้องกันระดับพื้นฐาน-กลางที่ครอบคลุมสถานการณ์ทั่วไปของร้านค้า ถ้าธุรกิจมีความเสี่ยงสูงหรือเงินหมุนเวียนจำนวนมาก แนะนำให้ให้ผู้เชี่ยวชาญด้านความปลอดภัยตรวจสอบ `firestore.rules` อีกครั้งก่อนใช้งานจริง

## โครงสร้างระบบ

- **พนักงาน (staff)**: บันทึกรายการใหม่ (เลือกฝั่งเงินหมุนเวียนที่เกี่ยวข้อง), ดูและแก้ไขรายการของตัวเอง (เฉพาะตอนยังไม่ถูกตรวจสอบ), พิมพ์ใบเบิกของรายการตัวเองหลังอนุมัติแล้ว, และเข้าถึง **"ใบเบิกเงินโอน"** ในโมดูลโอนจ่ายได้ (สร้าง/ดูทุกใบ แก้ไขได้เฉพาะใบของตัวเอง — ไม่เห็น "ใบโอนจ่าย" หรือหน้าจัดการบัญชีธนาคาร)
- **เจ้าของ/ผู้จัดการ (owner)**: เห็นรายการของทุกคนทุกฝั่ง, อนุมัติ (พร้อมเซ็นชื่อออนไลน์) / ตีกลับ / ยกเลิกรายการ, แก้ไขข้อมูลย้อนหลังได้ (มีเหตุผล+ประวัติ), จัดการสิทธิ์ผู้ใช้งานในเมนู "ผู้ใช้งาน", ตั้งค่า/เติมเงินงบค่าใช้จ่ายในเมนู "งบค่าใช้จ่าย", ดูและพิมพ์รายงาน Statement ในเมนู "รายงาน", และเป็นคนเดียวที่เข้าโมดูล "โอนจ่าย" (บัญชีธนาคาร) ได้
- **ผู้อ่าน (guest)**: ดูรายการที่อนุมัติแล้วทั้งหมด + ยอดคงเหลืองบค่าใช้จ่าย + รายงาน Statement ได้อย่างเดียว กดอนุมัติ/แก้ไข/ลบ/บันทึกรายการใหม่ไม่ได้ และ **มองไม่เห็นโมดูล "โอนจ่าย" เลย** เหมาะสำหรับผู้ร่วมหุ้น/นักบัญชีที่แค่ต้องการติดตามตัวเลข
- ผู้สมัครใหม่ทุกคนจะอยู่ในสถานะ **"รออนุมัติ" (pending)** จนกว่าเจ้าของจะกำหนดสิทธิ์ให้ (เลือกได้ว่าจะเป็นพนักงาน / ผู้อ่าน / เจ้าของ)
- **ฝั่งเงินหมุนเวียน (Funds)**: ระบบรองรับได้หลายฝั่งไม่จำกัด เช่น "หน้าร้าน" และ "ออกส่งสินค้าและเบี้ยเลี้ยง" — เจ้าของเป็นผู้สร้างฝั่งและตั้งยอดตั้งต้น ทุกรายการรายรับ/รายจ่ายต้องระบุว่าเป็นของฝั่งไหน ยอดคงเหลือของแต่ละฝั่งคำนวณจาก ยอดตั้งต้น + เงินที่เติมเข้า + รายรับที่อนุมัติแล้ว − รายจ่ายที่อนุมัติแล้ว โดยอัตโนมัติแบบเรียลไทม์
- **เข้าสู่ระบบด้วยชื่อผู้ใช้และ PIN 6 หลัก** — บัญชีเดิมอาจยังใช้ PIN 4-6 หลักระหว่าง migration เท่านั้น

## ขั้นตอนที่ 1: สร้างโปรเจกต์ Firebase

1. ไปที่ https://console.firebase.google.com แล้วกด **สร้างโปรเจกต์ (Add project)**
2. ตั้งชื่อโปรเจกต์ เช่น `my-shop-cash-ledger` แล้วกดสร้างจนเสร็จ
3. ในเมนูซ้าย ไปที่ **Build > Authentication** กด **Get started** แล้วเปิดใช้งานผู้ให้บริการ **Email/Password**
4. ไปที่ **Build > Firestore Database** กด **Create database** เลือกโหมด **Production mode** และเลือก location ที่ใกล้ร้าน (เช่น `asia-southeast1`)
5. ไปที่ **Project settings (รูปเฟือง) > General** เลื่อนลงไปที่ "Your apps" กดไอคอน **</>** (Web) เพื่อสร้างเว็บแอป ตั้งชื่ออะไรก็ได้ แล้วคัดลอกค่า `firebaseConfig` ที่ได้ไว้ (จะใช้ในขั้นตอนที่ 3)

> **ไม่ต้องสร้าง Storage** — แอปนี้ไม่ใช้ Firebase Storage เลย (ดูรายละเอียดในหัวข้อ "เรื่อง Firebase Storage" ด้านล่างของไฟล์นี้) จึงอยู่ในแพ็กฟรี Spark ได้โดยไม่ต้องผูกบัตรเครดิต ข้าม Storage ไปได้เลย

## ขั้นตอนที่ 2: ตั้งค่ากฎความปลอดภัย (สำคัญมาก)

อัปโหลดกฎจากไฟล์ในโปรเจกต์นี้เพื่อให้ระบบป้องกันทุจริตทำงาน:

**วิธีที่ 1 — ผ่านหน้าเว็บ (ง่ายที่สุด)**
- ไปที่ **Firestore Database > Rules** คัดลอกเนื้อหาทั้งหมดจากไฟล์ `firestore.rules` ในโปรเจกต์นี้ไปวางแทนของเดิม แล้วกด **Publish**

**วิธีที่ 2 — ผ่าน Firebase CLI**
```bash
npm install -g firebase-tools
firebase login
firebase use --add   # เลือกโปรเจกต์ที่สร้างไว้
firebase deploy --only firestore:rules,firestore:indexes
```

## ขั้นตอนที่ 3: ตั้งค่าโปรเจกต์และรันบนเครื่องตัวเอง (ทดสอบก่อน deploy)

```bash
npm install
```

สร้างสำเนา `.env.example` ชื่อ `.env` (บน PowerShell ใช้ `Copy-Item .env.example .env`; บน macOS/Linux ใช้ `cp .env.example .env`)

เปิดไฟล์ `.env` แล้วใส่ค่าจาก `firebaseConfig` ที่คัดลอกไว้ในขั้นตอนที่ 1:

```
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=...
VITE_FIREBASE_PROJECT_ID=...
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_APP_ID=...
```

รันทดสอบ:
```bash
npm run dev
```

หากยังไม่ได้ตั้งค่าหรือ Firebase config ไม่ถูกต้อง แอปจะแสดงรายการตัวแปรที่ต้องตรวจสอบแทนหน้าจอว่าง หลังแก้ `.env` ให้หยุดแล้วเริ่ม dev server ใหม่

## ขั้นตอนที่ 4: ตั้งบัญชีเจ้าของร้านคนแรก (สำหรับระบบใหม่)

สำหรับโปรเจกต์ Firestore ใหม่ที่ยังไม่มี `meta/setup` การสมัครบัญชีแรกจะสร้างโปรไฟล์ owner, mapping ชื่อผู้ใช้ และเอกสาร setup ใน batch เดียว ระบบปฏิเสธ bootstrap ซ้ำหากมีผู้สมัครพร้อมกัน

1. เปิดเว็บแอป กด **ลงทะเบียนที่นี่** กรอกชื่อ-นามสกุลและชื่อผู้ใช้ของเจ้าของร้าน แล้วตั้ง PIN 6 หลัก (พิมพ์ยืนยันอีกครั้ง)
2. กด "ยืนยันสมัครใช้งาน" — ระบบจะพาเข้าหน้าหลักทันที (ไม่ขึ้นหน้ารออนุมัติ) เพราะเป็นบัญชีแรกของระบบ
3. จากนี้สามารถไปที่เมนู **"ผู้ใช้งาน"** เพื่อเพิ่มพนักงาน/ผู้อ่านโดยตรงจากหน้าเว็บ หรืออนุมัติคนที่สมัครเองตามมาก็ได้ (ดูรายละเอียดในหัวข้อ "การเพิ่มพนักงาน/ผู้อ่าน" ด้านล่าง)

> **ระบบที่มีข้อมูลเดิมอยู่แล้ว:** อย่าสมัครใหม่เพื่อให้ได้ owner คนแรก ให้ใช้บัญชีเดิมและทำตามขั้นตอน "ย้ายบัญชีเดิมจาก PIN-only" ด้านล่าง

## ขั้นตอนที่ 4.5: สร้างฝั่งเงินหมุนเวียน (ทำครั้งเดียว ก่อนให้พนักงานเริ่มบันทึก)

1. ในฐานะเจ้าของร้าน ไปที่เมนู **"งบค่าใช้จ่าย"**
2. กรอกแบบฟอร์ม "เพิ่มฝั่งเงินหมุนเวียนใหม่" สร้างฝั่งแรก: ชื่อ **หน้าร้าน** ยอดเงินตั้งต้น **30000**
3. สร้างฝั่งที่สอง: ชื่อ **ออกส่งสินค้าและเบี้ยเลี้ยง** ยอดเงินตั้งต้น **20000**
4. จะเห็นการ์ดของทั้งสองฝั่งพร้อมยอดคงเหลือปัจจุบัน และช่องสำหรับ **"เติมเงินเข้างบค่าใช้จ่าย"** เมื่อเจ้าของนำเงินมาเติมเข้าฝั่งใดฝั่งหนึ่งภายหลัง (เช่น เติมเงินหมุนเวียนหน้าร้านกลับไป 30,000 ทุกสิ้นเดือน) — จำนวนที่กรอกจะถูกบวกเข้ายอดคงเหลือทันที พร้อมเก็บประวัติการเติมเงินไว้ให้ตรวจสอบย้อนหลัง

จากนั้นเมื่อพนักงานกด "+ บันทึกใหม่" จะมีให้เลือกฝั่งเงินหมุนเวียนก่อนกรอกรายการเสมอ

## ขั้นตอนที่ 5: ขึ้นเว็บจริงบน Netlify

**วิธีที่ 1 — ลากวางโฟลเดอร์ (เร็วที่สุด ไม่ต้องใช้ Git)**
```bash
npm run build
```
จากนั้นไปที่ https://app.netlify.com/drop แล้วลากโฟลเดอร์ `dist` ที่ได้ไปวาง — จะได้ลิงก์เว็บทันที (แต่ต้องตั้ง environment variables ก่อน build ทุกครั้ง วิธีนี้เหมาะกับทดสอบเร็วๆ)

**วิธีที่ 2 — เชื่อมกับ GitHub (ทำแล้ว แนะนำให้ใช้ เพราะจะมีการแก้ไข/เพิ่มฟีเจอร์ต่อเรื่อยๆ ในอนาคต)**

โปรเจกต์นี้ initialize git และ commit แรกไว้ให้แล้ว (ดูขั้นตอนใน "เชื่อมต่อ GitHub" ด้านล่าง) เหลือแค่สร้าง repo บน GitHub แล้ว push ขึ้นไป จากนั้นเชื่อม Netlify กับ repo นั้น — ทุกครั้งที่แก้โค้ดแล้ว push ใหม่ เว็บจะ deploy ให้อัตโนมัติ

## ขั้นตอนที่ 5.5: เชื่อมต่อ GitHub

**5.5.1 — สร้าง repo เปล่าบน GitHub**
1. ไปที่ https://github.com/new
2. ตั้งชื่อ repo เช่น `cash-ledger` เลือก **Private** (แนะนำ เพราะโค้ดมีโครงสร้างข้อมูลธุรกิจอยู่)
3. **ห้ามติ๊ก** "Add a README file" / .gitignore / license ใดๆ ทั้งสิ้น (ปล่อยเป็น repo เปล่า เพราะโปรเจกต์นี้มีไฟล์พวกนี้และมี git history ของตัวเองอยู่แล้ว) แล้วกด **Create repository**
4. หน้าที่ได้จะมีคำสั่งให้คัดลอก URL ของ repo ไว้ เช่น `https://github.com/<username>/cash-ledger.git`

**5.5.2 — Push โค้ดที่แตกไฟล์ไว้ขึ้น GitHub**

เปิด terminal ในโฟลเดอร์โปรเจกต์ที่แตกไฟล์ zip ออกมา (จะมีโฟลเดอร์ `.git` ซ่อนอยู่แล้วพร้อม commit แรกให้):
```bash
git remote add origin https://github.com/<username>/cash-ledger.git
git push -u origin main
```
ใส่ username/password (หรือ Personal Access Token ถ้า GitHub ขอ — ดูวิธีสร้างได้ที่ Settings > Developer settings > Personal access tokens) แล้ว push จะขึ้นไปพร้อม commit ประวัติเริ่มต้น

**5.5.3 — เชื่อม Netlify กับ repo นี้**
1. ที่ Netlify กด **Add new site > Import an existing project**
2. เลือก **GitHub** แล้วอนุญาตให้ Netlify เข้าถึง แล้วเลือก repo `cash-ledger`
3. Build command: `npm run build`, Publish directory: `dist` (ระบบจะอ่านจาก `netlify.toml` ให้อัตโนมัติอยู่แล้ว ไม่ต้องกรอกเองก็ได้)
4. ไปที่ **Site configuration > Environment variables** เพิ่มตัวแปรทั้ง 5 ตัวเดียวกับในไฟล์ `.env` ของคุณ (ค่าจาก Firebase Console ในขั้นตอนที่ 1)
5. กด **Deploy site**

จากนี้ไปทุกครั้งที่ต้องการแก้ไข/เพิ่มฟีเจอร์: แก้โค้ดในเครื่อง → `git add -A && git commit -m "อธิบายสิ่งที่แก้"` → `git push` → Netlify จะ build และขึ้นเว็บใหม่ให้อัตโนมัติภายในไม่กี่นาที ไม่ต้อง build/ลากอัปโหลดเองอีก

## วิธีใช้งานประจำวัน

- **พนักงาน**: กด "+ บันทึกใหม่" → เลือกฝั่งเงินหมุนเวียน (หน้าร้าน / ออกส่งสินค้าและเบี้ยเลี้ยง) → เลือกรายรับ/รายจ่าย → กรอกจำนวนเงิน/รายละเอียด/เงินทอน → แนบรูปหลักฐาน → บันทึก (รายการจะรอเจ้าของตรวจสอบ)
- **เจ้าของอนุมัติ**: เข้าเมนู "ตรวจสอบทั้งหมด" กรองตามสถานะ/พนักงาน/ฝั่ง แล้วกดเข้าไปดูรายละเอียดแต่ละรายการ → กด "อนุมัติ (เซ็นยืนยัน)" → **วาดลายเซ็นในกรอบที่ขึ้นมา** → ยืนยัน — รายการจะกลายเป็น "อนุมัติแล้ว" และถือว่า **เบิกสำเร็จ** ตั้งแต่วินาทีนั้น (ถ้ายังไม่เซ็น จะกดอนุมัติไม่ผ่าน)
- **พิมพ์ใบเบิก**: หลังอนุมัติแล้ว จะมีปุ่ม "พิมพ์ใบเบิก" ในหน้ารายละเอียดรายการ กดแล้วจะเปิดเอกสารพร้อมพิมพ์/บันทึกเป็น PDF มีลายเซ็นผู้อนุมัติแนบอยู่ในเอกสารด้วย
- **แก้ไขรายการ**: กดเข้ารายการ → "แก้ไขรายการ" → แก้ค่าที่ผิด → ใส่เหตุผล (บังคับ) → บันทึก ระบบจะเก็บ before/after ไว้ให้ตรวจสอบย้อนหลังได้เสมอ
- **เติมเงินเข้างบค่าใช้จ่าย**: เจ้าของเข้าเมนู "งบค่าใช้จ่าย" กรอกจำนวนเงินในช่อง "เติมเงินเข้างบค่าใช้จ่าย" ของฝั่งที่ต้องการ แล้วกด "เติมเงิน" ยอดคงเหลือของฝั่งนั้นจะปรับเพิ่มทันที
- **พิมพ์รายงาน Statement**: เจ้าของเข้าเมนู "รายงาน" เลือกฝั่งเงินหมุนเวียน แล้วเลือกช่วงวันที่เอง หรือกดปุ่มลัด "วันนี้ / เดือนนี้ / ปีนี้" ระบบจะแสดงยอดยกมา รายการเคลื่อนไหวทั้งหมดในช่วงนั้น (พร้อมยอดคงเหลือหลังแต่ละรายการ) และยอดคงเหลือปิดงวด กดปุ่ม "พิมพ์รายงาน" เพื่อพิมพ์หรือบันทึกเป็น PDF

## โมดูล "โอนจ่าย" (เงินโอนผ่านธนาคาร ไม่ใช่เงินสด)

โมดูลนี้แยกต่างหากจากระบบเงินสด/งบค่าใช้จ่ายหมุนเวียนทั้งหมด ไม่มีขั้นตอนอนุมัติหรือเซ็นชื่อ ใช้สำหรับบันทึกวงจรการเบิกเงินโอนเข้าบัญชี แล้วโอนจ่ายออกไปยังผู้รับปลายทาง โดยตัดยอดกันเองอัตโนมัติ

**สิทธิ์การเข้าถึง**: **"ใบเบิกเงินโอน"** เปิดให้พนักงาน (staff) เข้าถึงได้ด้วย — สร้างใบเบิกใหม่ได้ ดูใบเบิกของทุกคนได้ (เห็นภาพรวมว่าใครเบิกอะไรไปบ้าง) แต่แก้ไข/ลบได้เฉพาะใบของตัวเองเท่านั้น (ใบของคนอื่นจะเห็นเป็นแบบอ่านอย่างเดียว) ส่วน **"ใบโอนจ่าย"** และ **"บัญชีธนาคาร & หมวดหมู่"** ยังคงเป็นสิทธิ์เจ้าของร้านเท่านั้นเหมือนเดิม พนักงานมองไม่เห็น 2 ส่วนนี้เลย

**แนวคิดของระบบ**
- **บัญชี A** = บัญชีธนาคารของเรา ใช้รับเงินตอนเบิก และเป็นบัญชีต้นทางตอนโอนจ่ายออก
- **บัญชี B** = บัญชีปลายทางของผู้รับโอน (ซัพพลายเออร์ พนักงาน ฯลฯ)
- **ใบเบิกเงินโอน**: รายการของสิ่งที่ต้องจ่าย (หมวดหมู่ + รายละเอียด + ยอดเงิน หลายบรรทัด) รวมเป็นยอดที่ "เบิกเข้า" บัญชี A
- **ใบโอนจ่าย**: บันทึกการโอนเงินจริงจากบัญชี A ไปยังบัญชี B แต่ละใบเลือกได้ว่าจะ "ตัดยอด" กับใบเบิกใบไหน — ตัดได้หลายครั้งจนกว่าจะครบยอดของใบเบิกนั้น (ระบบคำนวณ "ยอดคงเหลือ" ของแต่ละใบเบิกให้อัตโนมัติจากผลรวมใบโอนจ่ายที่ผูกไว้)

**วิธีใช้งาน**
1. เมนู **"โอนจ่าย" > "บัญชีธนาคาร & หมวดหมู่"**: บันทึกบัญชี A (บัญชีของเรา) และบัญชี B (บัญชีผู้รับโอน) ไว้เป็นรายการโปรดก่อนใช้งานครั้งแรก พร้อมตั้งหมวดหมู่รายจ่ายที่ใช้บ่อย (เช่น ค่าน้ำมัน, เบี้ยเลี้ยง)
2. แท็บ **"ใบเบิกเงินโอน"** กด "+ สร้างใบเบิกใหม่" → เลือกบัญชี A ที่จะรับเงินเข้า + วันที่เบิก (กรอกครั้งเดียว) → เพิ่มบรรทัดรายการได้ไม่จำกัด (หมวดหมู่/รายละเอียด/ยอดเงิน แต่ละบรรทัดมีเลขลำดับอัตโนมัติ) → กดบันทึกทีเดียวทั้งใบ ระบบจะออกเลขที่ใบเบิกอัตโนมัติ (เช่น WR-0001) กลับมาแก้ไข เพิ่ม ลบบรรทัด หรือลบทั้งใบได้ตลอด และพิมพ์/บันทึกเป็น PDF ได้จากปุ่ม "พิมพ์ / PDF"
3. แท็บ **"ใบโอนจ่าย"** กด "+ สร้างใบโอนจ่ายใหม่" → เลือกบัญชี A ต้นทาง → เลือกใบเบิกที่จะตัดยอดด้วย (ระบบจะโชว์ยอดคงเหลือของใบเบิกนั้นให้ดูก่อนบันทึก) → เพิ่มบรรทัดการโอน (วันที่โอน/บัญชีผู้รับโอน B/ยอดเงิน/หมายเหตุ) หลายรายการได้ในครั้งเดียว → กดบันทึก ระบบออกเลขที่ใบโอนจ่ายอัตโนมัติ (เช่น TP-0001) ถ้ายอดรวมเกินยอดคงเหลือของใบเบิก ระบบจะเตือนไว้ให้ตรวจสอบ (ไม่ได้บล็อกการบันทึก เผื่อกรณีมีเหตุผลพิเศษ) แก้ไข/ลบ/พิมพ์ PDF ได้เช่นเดียวกับใบเบิก
4. หน้ารายการ "ใบเบิกเงินโอน" จะโชว์สถานะ "ตัดยอดครบแล้ว" หรือ "คงเหลือ X บาท" ของแต่ละใบให้เห็นทันทีว่าใบไหนยังจ่ายไม่ครบ

## Sidebar สำหรับจอเดสก์ท็อป (≥ 1024px)

- จอใหญ่ (`lg` ขึ้นไป) ใช้ **Sidebar ด้านซ้ายแบบตายตัว** (`src/components/Sidebar.jsx`) แทนแถบเมนูบนแนวนอนทั้งหมด — โลโก้ด้านบน, ปุ่ม "บันทึกใหม่" เด่น, เมนูหลักพร้อมไอคอนเรียงเป็นแนวตั้ง (รายการของฉัน/ตรวจสอบทั้งหมด/ผู้ใช้งาน/งบค่าใช้จ่าย/รายงาน/โอนจ่าย ตามสิทธิ์), และการ์ดโปรไฟล์+เปลี่ยน PIN+ออกจากระบบอยู่ด้านล่างสุด
- จอเล็กกว่า `lg` (มือถือ+แท็บเล็ตทุกขนาด) ยังใช้แถบบนบาง + แถบเมนูล่างแบบแอปเหมือนเดิม (`src/components/Navbar.jsx`) — รวมกลไก "เปิดเมนู" ให้เป็นแผงเดียวกันทั้งจากปุ่มโปรไฟล์มุมบนและแท็บ "เมนู" ด้านล่าง ไม่มีเมนูซ้ำซ้อนสองแบบอีกต่อไป
- ไม่พบโค้ด/สคริปต์ badge "Powered by Netlify" ในโปรเจกต์นี้เลย (ค้นทั้ง `index.html` และทุกไฟล์ component แล้ว) — ถ้าเห็นบนเว็บจริง อาจมาจากฟีเจอร์ badge ที่ต้องเปิดเองในตั้งค่า Netlify ไม่ใช่โค้ดของแอป

## ปรับให้ใช้งานง่ายบนมือถือ

- **แถบเมนูล่างแบบแอปมือถือ** (โผล่เฉพาะจอมือถือจริง ใต้ขนาดแท็บเล็ต): มีปุ่ม "หน้าแรก", เมนูตามบทบาท (เช่น เจ้าของร้านเห็น "ตรวจสอบ" กับ "รายงาน", พนักงานเห็น "ใบเบิก"), ปุ่ม **"+" ลอยตรงกลางแบบยกขึ้น** สำหรับบันทึกรายการใหม่ (กดถึงได้ด้วยนิ้วโป้งง่ายๆ ไม่ต้องเอื้อมขึ้นบนสุดจอ), และปุ่ม "เมนู" เปิดแผงรายการทั้งหมดแบบเลื่อนขึ้นจากด้านล่าง (bottom sheet) พร้อมชื่อผู้ใช้/เปลี่ยน PIN/ออกจากระบบ
- **แปลงตารางกรอกรายการหลายบรรทัด** (ในใบเบิกเงินโอน และใบโอนจ่าย) จากตารางที่ต้องเลื่อนแนวนอนบนจอเล็ก ให้กลายเป็น **การ์ดเรียงตามแนวตั้งทีละรายการ** แทนบนมือถือ (จอกลาง/ใหญ่ยังเป็นตารางปกติเหมือนเดิม)
- เว้นระยะด้านล่างของเนื้อหาให้พอดี ไม่ให้แถบเมนูล่างบังเนื้อหาส่วนท้ายของแต่ละหน้า

## หน้าตาใหม่: Navbar และ Dropdown แบบ Popup ค้นหาได้

- **หน้า "รายการของฉัน"** ปรับใหม่ทั้งหน้า: ช่องค้นหา (ค้นได้ทั้งรายละเอียด/หมวดหมู่/หมายเหตุ) + ตัวกรองหมวดหมู่ (popup ค้นหาได้) + ปุ่มลัดกรองวันที่ (วันนี้/7 วันล่าสุด/เดือนนี้) จัดเรียงอยู่ในกรอบเดียวกับปุ่ม "บันทึกใหม่" ด้านบนสุด, การ์ดรายการมีไอคอนวงกลมสีเขียว/แดงแยกรายรับ-รายจ่ายให้เห็นชัดตั้งแต่มองแวบแรก พร้อม badge ประเภทและหมวดหมู่, หน้าจอว่างเปล่า (ยังไม่มีรายการ / ค้นหาไม่เจอ) มีไอคอนพร้อมคำแนะนำแทนที่จะปล่อยว่างโล่ง — พื้นหลังแอปปรับให้ตัดกับการ์ดขาวชัดเจนขึ้นด้วย

- **การ์ดสรุปยอด** (component `src/components/MetricCard.jsx`) แยกเป็น 3 การ์ดวางเรียงแนวนอน (พับเป็นแนวตั้งอัตโนมัติบนมือถือ): "รายรับรวม" สีเขียว/ไอคอนลูกศรขึ้น, "รายจ่ายรวม" สีแดง/ไอคอนลูกศรลง, และการ์ดหลัก ("คงเหลือสุทธิ" หรือ "รอตรวจสอบ" แล้วแต่หน้า) พื้นเข้มเด่นแยกออกมาให้เห็นชัดว่าเป็นตัวเลขสำคัญที่สุด ทุกการ์ดมีเงาบางๆ + กรอบซอฟต์

- **Navbar** จัดกลุ่มเมนูใหม่ทั้งหมด (component `src/components/Navbar.jsx`): เมนูหลักเรียงเป็นแถบเดียวดูสะอาดขึ้น พร้อมไอคอน (lucide-react), พับเป็นเมนูแฮมเบอร์เกอร์อัตโนมัติบนจอมือถือ/แท็บเล็ต, ปุ่ม "บันทึกใหม่" เด่นแยกเป็นปุ่มสีหลักติดตาตลอด, ข้อมูลผู้ใช้/เปลี่ยน PIN/ออกจากระบบ ย้ายไปรวมในเมนูโปรไฟล์มุมขวาบน (คลิกที่ชื่อ/ไอคอนวงกลม)
- **Dropdown ทั้งหมดในระบบเปลี่ยนเป็น popup ค้นหาได้** (component `src/components/Combobox.jsx`) แทนกล่อง `<select>` เดิม — คลิกแล้วมีช่องพิมพ์ค้นหาขึ้นมา พิมพ์คำที่อยู่ตรงไหนของชื่อก็เจอ (ไม่ใช่แค่ขึ้นต้น) เช่น พิมพ์ "เดิน" เจอ "ค่าเดินทาง", ใช้ลูกศรขึ้น-ลงและ Enter เลือกด้วยคีย์บอร์ดได้ด้วย ใช้กับ: เลือกบัญชีธนาคาร (โอนจ่าย), เลือกใบเบิกที่จะตัดยอด, ตัวกรองพนักงาน/ฝั่งงบค่าใช้จ่ายในหน้ารายการ, และตั้งบทบาทผู้ใช้งาน
  - ข้อยกเว้น: ช่อง "หมวดหมู่" ตอนบันทึกรายการยังคงเป็นช่องพิมพ์อิสระพร้อมคำแนะนำ (ไม่ใช่ popup แบบเลือกอย่างเดียว) เพราะต้องรองรับการพิมพ์หมวดหมู่ใหม่ที่ยังไม่เคยมีในลิสต์ด้วย

## กราฟภาพรวมรายรับ-รายจ่าย

ในหน้า "รายงาน" (Statement) นอกจากตารางรายการแล้ว ยังมีกราฟ 2 อันแสดงต่อท้ายให้เห็นภาพรวมของช่วงที่เลือกไว้:

- **แนวโน้มยอดคงเหลือ**: กราฟเส้นแสดงยอดคงเหลืองบค่าใช้จ่ายที่เลือกไล่ตามวันที่ในช่วงนั้น เห็นได้ทันทีว่าเงินหมุนเวียนขึ้น-ลงตอนไหนบ้าง
- **รายจ่ายตามหมวดหมู่**: กราฟแท่งสรุปยอดรายจ่ายรวมแยกตามหมวดหมู่ที่ตั้งไว้ (เช่น ค่าวัตถุดิบ, ค่าน้ำมัน) เรียงจากมากไปน้อย ช่วยเห็นว่าเงินส่วนใหญ่หมดไปกับอะไร — แสดงเฉพาะรายการที่มีการตั้งหมวดหมู่ไว้ตอนบันทึก

กราฟทั้งสองอันนี้เป็นข้อมูลดูบนหน้าจอเท่านั้น ไม่รวมอยู่ในเอกสารที่พิมพ์/บันทึกเป็น PDF (กันเอกสาร Statement ทางการดูรกและพิมพ์ยาก)

## การแจ้งเตือนในแอป

ไม่มีการแจ้งเตือนแบบ push (ต้องใช้ Cloud Functions ซึ่งเสียเงิน) แต่มีการแจ้งเตือนแบบเห็นทันทีตอนเปิดแอปอยู่:

- **ตัวเลขแจ้งเตือนข้างเมนู (เฉพาะเจ้าของร้าน)**: เมนู "ตรวจสอบทั้งหมด" จะมีวงกลมแดงบอกจำนวนรายการเงินสดที่รอตรวจสอบ และเมนู "ผู้ใช้งาน" จะบอกจำนวนบัญชีที่รออนุมัติสิทธิ์ ทั้งสองอัปเดตแบบเรียลไทม์
- **แบนเนอร์เตือนงบค่าใช้จ่ายใกล้หมด**: แสดงที่หน้าหลักของพนักงานและเจ้าของร้าน (ไม่แสดงกับผู้อ่าน) เมื่อยอดคงเหลือของฝั่งไหนต่ำกว่า **20% ของยอดตั้งต้น** จะมีแบนเนอร์สีเหลืองเตือนทันทีพร้อมยอดคงเหลือปัจจุบัน เพื่อเตือนให้เติมเงินเข้างบค่าใช้จ่ายก่อนเงินขาดมือ (ปรับเกณฑ์ 20% นี้ได้ที่ค่า `LOW_BALANCE_RATIO` ในไฟล์ `src/components/LowFundBalanceBanner.jsx`)

## หมวดหมู่และรูปหลักฐานหลายใบ สำหรับรายการเงินสดทั่วไป

- **หมวดหมู่**: เจ้าของร้านตั้งหมวดหมู่ที่ใช้บ่อยไว้ล่วงหน้าได้ที่เมนู "งบค่าใช้จ่าย" (เช่น ค่าวัตถุดิบ, ค่าน้ำมัน, ค่าขนส่ง) พนักงานเลือกจากลิสต์หรือพิมพ์เองก็ได้ตอนบันทึกรายการใหม่ — ไม่บังคับกรอก
- **แนบรูปหลักฐานได้หลายรูปต่อ 1 รายการ**: สูงสุด 3 รูป (เผื่อกรณีมีหลายใบเสร็จในรายการเดียว) แต่ละรูปจะถูกบีบอัดอัตโนมัติเหลือ ~120 KB เพื่อให้ยังอยู่ในขอบเขตปลอดภัยของ Firestore ถ้ารวมกันมีขนาดใหญ่เกินไป ระบบจะเตือนให้ลดจำนวนรูปลง

## เรื่องการเข้าสู่ระบบด้วยชื่อผู้ใช้และ PIN

บัญชีใหม่ใช้ **ชื่อผู้ใช้และ PIN ตัวเลข 6 หลัก** โดยเบื้องหลังยังใช้ Firebase Authentication แบบ email/password และอีเมลสุ่ม `@pin.local` (ไม่มีการส่งอีเมลจริง) ระบบเก็บ mapping **ชื่อผู้ใช้ → UID/อีเมลภายใน** ใน `pinDirectory`; ไม่เก็บ PIN ไว้ใน `users` หรือใช้ PIN เป็น Document ID สำหรับบัญชีใหม่ PIN จะถูกเติมเลข 0 ด้านหน้าเฉพาะตอนแปลงเป็นรหัสผ่านภายใน Firebase เท่านั้น

- ชื่อผู้ใช้ต้องไม่ซ้ำกัน และใช้ตัวอักษรอังกฤษตัวพิมพ์เล็ก ตัวเลข `.`, `_`, `-` โดยขึ้นต้นด้วยตัวอักษร (3-24 ตัว)
- ผู้ใช้เปลี่ยน PIN ของตัวเองได้จากเมนู "เปลี่ยน PIN" โดยยืนยัน PIN ปัจจุบันก่อน ตั้ง PIN ใหม่ 6 หลัก
- เจ้าของร้านเปลี่ยนหรือรีเซ็ตรหัสผ่านของผู้ใช้อื่นจากหน้าเว็บไม่ได้ หากลืม PIN ต้องใช้กระบวนการกู้บัญชีที่เจ้าของร้านจัดการอย่างปลอดภัย ไม่ควรสร้างบัญชีซ้ำเพื่อทดแทนโดยไม่ตรวจสอบรายการและประวัติเดิม

### ย้ายบัญชีเดิมจาก PIN-only

ฐานข้อมูลเดิมที่ `meta/setup.loginMode` ยังไม่ใช่ `username` จะคงให้บัญชีเดิมเข้าสู่ระบบด้วย PIN เดิมระหว่างย้ายข้อมูล เจ้าของร้านควรเข้าสู่ระบบด้วยบัญชีเดิม แล้วไปที่ **ผู้ใช้งาน > ย้ายบัญชีไปใช้ชื่อผู้ใช้**:

1. ตรวจจำนวนเจ้าของที่ยังใช้งาน แล้วกดเตรียมจำนวนเจ้าของร้าน (จำเป็นเฉพาะฐานข้อมูลเดิมที่ยังไม่มี `ownerCount`)
2. กำหนดชื่อผู้ใช้และย้ายบัญชีทีละรายการ การย้ายแต่ละบัญชีจะย้าย mapping ใน `pinDirectory` และลบค่า PIN ที่เก็บใน `users` ใน batch เดียวกัน
3. เมื่อย้ายครบทุกบัญชี ให้เปิดใช้ "ชื่อผู้ใช้ + PIN"; หลังจากนั้นให้ลงชื่อเข้าใช้ด้วยชื่อผู้ใช้และ PIN 6 หลัก (PIN เดิมที่สั้นกว่า 6 หลักถูกเติมศูนย์ด้านหน้าเป็นรหัสผ่านภายใน ให้เปลี่ยนเป็น PIN ใหม่ 6 หลักจากเมนูหลังเข้าสู่ระบบ)

อย่าสมัครบัญชีใหม่เพื่อแทนเจ้าของเดิม และอย่าลบ/แก้เอกสาร Firebase Auth หรือ Firestore ด้วยตนเองระหว่าง migration ข้อมูล audit เริ่มบันทึกตั้งแต่เริ่มใช้รุ่นนี้ ไม่มีการ backfill ประวัติเก่า การเปิด `username` mode ทำให้ lookup ด้วย PIN เดิมถูกปิดสำหรับผู้ใช้ทั่วไป

## เรื่องบทบาท "ผู้อ่าน (Guest)"

เพิ่มบทบาทที่ 3 นอกจากพนักงานกับเจ้าของ — เหมาะสำหรับคนที่แค่อยากติดตามตัวเลข (เช่น ผู้ร่วมหุ้น นักบัญชีภายนอก) โดยไม่ต้องให้สิทธิ์บันทึก/แก้ไขอะไร:

- เห็นได้: รายการที่ **อนุมัติแล้ว** ทั้งหมดทุกฝั่ง, ยอดคงเหลืองบค่าใช้จ่ายแบบเรียลไทม์, หน้ารายงาน Statement (พิมพ์ได้ด้วย)
- เห็นไม่ได้/ทำไม่ได้: บันทึกรายการใหม่, แก้ไข/อนุมัติ/ตีกลับรายการใดๆ, หน้าจัดการผู้ใช้งาน, หน้าตั้งค่างบค่าใช้จ่าย, และ **โมดูล "โอนจ่าย" ทั้งหมด** (ไม่เห็นเมนูเลย)
- วิธีตั้งค่า: เจ้าของร้านเพิ่มให้โดยตรงจากเมนู **"ผู้ใช้งาน" > "+ เพิ่มพนักงาน"** เลือกบทบาท "ผู้อ่าน" ได้เลย หรือให้คนนั้นสมัครสมาชิกเอง (จะอยู่ในสถานะ "รออนุมัติ") แล้วเจ้าของเข้าเมนู "ผู้ใช้งาน" กดปุ่ม "ตั้งเป็นผู้อ่าน" ให้ทีหลังก็ได้

## การเพิ่มพนักงาน/ผู้อ่าน (จากหน้าเว็บโดยตรง)

เจ้าของร้านเพิ่มพนักงานหรือผู้อ่านคนใหม่ได้เองจากเมนู **"ผู้ใช้งาน" > "+ เพิ่มพนักงาน"** โดยไม่ต้องรอให้คนนั้นสมัครเอง:

1. กรอกชื่อ-นามสกุลและชื่อผู้ใช้ เลือกบทบาท (พนักงาน / ผู้อ่าน / เจ้าของ)
2. ตั้ง PIN 6 หลักให้คนนั้น แล้วพิมพ์ยืนยันอีกครั้ง
3. กด "ยืนยันเพิ่มพนักงาน" — บัญชีจะใช้งานได้ทันที **ไม่ต้องผ่านสถานะ "รออนุมัติ"** เพราะเจ้าของร้านเป็นผู้สร้างเองโดยตรงอยู่แล้ว

**หมายเหตุทางเทคนิค**: ขั้นตอนนี้สร้างบัญชีผ่าน Firebase App สำรองชั่วคราวเบื้องหลัง เพื่อไม่ให้เซสชันของเจ้าของร้านที่ล็อกอินอยู่หลุดออกไป (ปกติแล้วการสร้างบัญชีใหม่ด้วย Firebase Auth จะสลับเซสชันไปเป็นบัญชีใหม่ทันทีถ้าไม่ป้องกันจุดนี้ไว้)

**การปิดใช้งานผู้ใช้**: ใช้ปุ่มเปิด/ปิดสถานะในหน้า "ผู้ใช้งาน" แทนการลบเอกสารจาก Firebase Console เพื่อคงรายการและประวัติ audit ไว้ การเปลี่ยนสิทธิ์/ปิดใช้งาน owner คนสุดท้ายและการแก้สิทธิ์บัญชีตัวเองถูกปฏิเสธโดย Firestore Rules

ผู้ใช้ที่เจ้าของเพิ่มจะได้รับชื่อผู้ใช้และ PIN ตั้งต้นจากเจ้าของผ่านช่องทางที่ปลอดภัย ผู้ใช้ควรเปลี่ยน PIN ของตัวเองจากเมนู "เปลี่ยน PIN" หลังเข้าสู่ระบบ

## หมายเหตุเรื่องค่าใช้จ่าย

Firebase Firestore/Auth และ Netlify มี free quotas ตามแผนและเงื่อนไขปัจจุบัน; ไม่มีการรับประกันว่าจะใช้ฟรีได้ทุกระดับการใช้งาน ควรตรวจสอบ quotas และราคาอย่างสม่ำเสมอ

## ปิดยอดเงินสดและประวัติการใช้งาน

- Owner และ staff ปิดยอดเงินสดของงบค่าใช้จ่ายได้ ระบบคำนวณยอดจากยอดตั้งต้น เงินเติมงบค่าใช้จ่าย และรายการเงินสดที่อนุมัติแล้ว โดยไม่รวมรายการโอน
- หากมีส่วนต่างต้องระบุเหตุผล การแก้ไขทำเป็นรายการใหม่อ้างอิงรายการเดิม เอกสารเดิมไม่ถูกแก้หรือลบ
- ประวัติปิดยอดและ `activityLogs` อ่านได้เฉพาะ owner; `auditLogs` เดิมยังคงอยู่และไม่มีการย้ายข้อมูลย้อนหลัง
- การปิดยอดเขียนผ่าน Netlify Function ซึ่งตรวจ Firebase ID token/role และคำนวณยอดจาก Firestore ฝั่ง server โดยตรง เพื่อไม่ให้ browser ส่งยอดระบบเอง
- ต้องตั้ง `FIREBASE_SERVICE_ACCOUNT_JSON` ใน Netlify environment variables เป็น JSON ของ service account ที่มีสิทธิ์ Firestore/Auth ตามจำเป็น ตัวแปรนี้ต้องไม่มี prefix `VITE_` และห้ามพิมพ์ลง log; หากแผนมีตัวเลือก scope ให้จำกัดไว้ที่ Functions
- ตั้ง environment variable `AWS_LAMBDA_JS_RUNTIME=nodejs22.x` ผ่าน Netlify UI แล้ว redeploy เพื่อให้ตรงกับ Node.js ขั้นต่ำของ Firebase Admin SDK รุ่นที่ใช้ (ตั้งผ่าน UI ไม่ใช่ `netlify.toml`)
- ห้ามใส่ service-account JSON ใน source, `.env` ที่ฝัง client, หรือส่งผ่าน chat; การใช้งาน Netlify/Firebase ต้องอยู่ภายใน free quotas หากต้องการคงค่าใช้จ่ายเป็นศูนย์
- ก่อนใช้งานจริง ให้ deploy Firestore rules และ composite index ก่อน แล้วจึง deploy site/function: `firebase deploy --only firestore:rules,firestore:indexes`

## เรื่อง Firebase Storage

**แอปนี้ไม่ใช้ Firebase Storage เลย** เพราะตั้งแต่ 3 กุมภาพันธ์ 2026 เป็นต้นมา Google กำหนดให้ Firebase Storage ต้องอัปเกรดโปรเจกต์เป็นแพ็ก **Blaze (pay-as-you-go)** เท่านั้นถึงจะใช้ได้ — แม้จะใช้ไม่เกินโควตาฟรีก็ต้องผูกบัตรเครดิตไว้กับโปรเจกต์อยู่ดี (จะไม่ถูกเรียกเก็บเงินถ้าไม่เกินโควตา แต่หลายคนไม่สะดวกผูกบัตร)

เพื่อให้ใช้แพ็กฟรี **Spark** ได้ 100% โดยไม่ต้องผูกบัตรอะไรเลย แอปนี้จึงออกแบบให้:
- รูปหลักฐาน/รูปเงินทอน/ลายเซ็นอนุมัติ ถูก**บีบอัดที่เครื่องผู้ใช้ก่อนอัปโหลด** (ย่อขนาดรูป + ลดคุณภาพ JPEG อัตโนมัติจนเหลือประมาณ 100-180 KB ต่อรูป) แล้วเก็บเป็นข้อความ base64 ฝังลงในเอกสาร Firestore โดยตรง แทนที่จะอัปโหลดไปเก็บที่ Storage
- ตอนแนบรูปในฟอร์มบันทึกรายการ จะเห็นข้อความ "บีบอัดแล้วเหลือ ~XX KB" ให้ตรวจสอบก่อนบันทึกเสมอ
- ข้อจำกัด: Firestore จำกัดขนาดเอกสารแต่ละอันไว้ที่ 1 MB ระบบบีบอัดไว้ให้อยู่ในขอบเขตที่ปลอดภัยแล้ว แต่ถ้ารูปต้นฉบับซับซ้อนมากเป็นพิเศษ (เช่น รูปความละเอียดสูงมากที่ยังบีบไม่ลงหลังพยายามหลายรอบ) อาจต้องถ่ายรูปใหม่ให้เรียบง่ายขึ้นเล็กน้อย

ถ้าในอนาคตอยากได้คุณภาพรูปที่สูงขึ้นและไม่ติดข้อจำกัดขนาดเอกสาร สามารถอัปเกรดเป็น Blaze แล้วขอให้ปรับโค้ดกลับไปใช้ Firebase Storage แทนได้ (Blaze ยังฟรีอยู่ถ้าไม่เกินโควตา แค่ต้องผูกบัตรไว้เฉยๆ)

## เรื่อง GitHub

โปรเจกต์นี้เชื่อมต่อ GitHub ให้แล้วตามขั้นตอนที่ 5.5 ด้านบน (git init + commit แรกไว้ในไฟล์ zip นี้เรียบร้อย เหลือแค่ push ขึ้น repo ที่สร้างใหม่) เพราะจะมีการแก้ไข/เพิ่มฟีเจอร์กันต่อเรื่อยๆ — วิธีนี้ทำให้ทุกครั้งที่แก้โค้ด แค่ `git push` เว็บก็ deploy ให้อัตโนมัติ ไม่ต้อง build/ลากอัปโหลดเองทุกรอบ และมีประวัติการแก้ไขเก็บไว้ย้อนดูได้ด้วย
