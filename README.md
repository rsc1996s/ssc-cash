# ระบบบันทึกรายรับ-รายจ่ายเงินสดหน้าร้าน

เว็บแอประบบบันทึกรายรับ-รายจ่ายเงินสด สำหรับหน้าร้าน ใช้งานได้จากมือถือหรือคอมพิวเตอร์เครื่องไหนก็ได้ (ข้อมูลอยู่บน Firebase แบบเรียลไทม์) มีระบบตรวจสอบและกันทุจริตในตัว

## ระบบป้องกันการทุจริตที่มีอยู่ในตัวแอป

1. **แนบหลักฐานภาพถ่ายบังคับ** — ทุกรายการต้องแนบรูปสลิป/ใบเสร็จ (และรูปเงินทอนสำหรับรายจ่าย) ก่อนบันทึกได้
2. **แยกบทบาทชัดเจน** — พนักงานบันทึกรายการ ส่วนเจ้าของ/ผู้จัดการเป็นผู้ตรวจสอบและอนุมัติ ทุกรายการเริ่มที่สถานะ "รอตรวจสอบ" เสมอ
3. **ห้ามลบถาวรโดยเด็ดขาด** — ไม่มีปุ่มลบในระบบเลย แม้แต่เจ้าของก็ลบไม่ได้ ถ้าต้องยกเลิกรายการจะใช้สถานะ "ยกเลิกรายการ" แทน ซึ่งยังคงอยู่ในระบบให้ตรวจสอบย้อนหลังได้
4. **แก้ไขได้แต่ต้องมีเหตุผลเสมอ** — การแก้ไขทุกครั้งต้องกรอกเหตุผล และระบบจะบันทึกลง "ประวัติการแก้ไข (Audit Trail)" อัตโนมัติ ว่าใครแก้ อะไร จากค่าไหนเป็นค่าไหน เมื่อไหร่ ประวัตินี้ลบไม่ได้และดูได้ในหน้ารายละเอียดของทุกรายการ
5. **พนักงานแก้รายการของตัวเองได้เฉพาะตอนที่ยังไม่ถูกตรวจสอบ** — เมื่อเจ้าของอนุมัติ/ตีกลับแล้ว พนักงานจะแก้ไขไม่ได้อีก (แก้ได้เฉพาะเจ้าของ และต้องมีเหตุผลด้วย)
6. **กฎทั้งหมดถูกบังคับที่ระดับฐานข้อมูล (Firestore Security Rules)** ไม่ใช่แค่ที่หน้าเว็บ — ต่อให้มีคนพยายามแก้โค้ดฝั่งหน้าเว็บหรือเรียก API ตรงๆ ก็ยังถูกกฎเหล่านี้บังคับอยู่ดี ดูรายละเอียดได้ในไฟล์ `firestore.rules`
7. **เวลาบันทึกใช้เวลาจากเซิร์ฟเวอร์ (serverTimestamp)** ป้องกันการตั้งนาฬิกาเครื่องปลอมวันที่
8. **ทุกรายการระบุผู้บันทึกและผู้ตรวจสอบชัดเจน** พร้อมประวัติเข้าถึงย้อนหลังได้ตลอด
9. **แยกเงินหมุนเวียนเป็นฝั่งๆ (Funds)** — เช่น หน้าร้าน / ออกส่งสินค้าและเบี้ยเลี้ยง แต่ละฝั่งมียอดตั้งต้นและยอดคงเหลือของตัวเอง แยกกันชัดเจน ไม่ปนกัน
10. **เบิกเงินสำเร็จได้ก็ต่อเมื่อ "อนุมัติ + เซ็นชื่อออนไลน์" เท่านั้น** — เจ้าของต้องลงลายเซ็นในระบบ (วาดบนหน้าจอ) ตอนกดอนุมัติทุกครั้ง ถ้ายังไม่เซ็นจะอนุมัติไม่ผ่านและพิมพ์ใบเบิกไม่ได้ กฎนี้ถูกบังคับซ้ำใน `firestore.rules` ด้วย ไม่ใช่แค่ที่หน้าเว็บ
11. **พิมพ์ใบเบิก/ใบรับเงินได้เฉพาะรายการที่อนุมัติและเซ็นแล้ว** ป้องกันการพิมพ์เอกสารมาอ้างสิทธิ์เบิกเงินก่อนได้รับอนุมัติจริง
12. **ไม่ใช้ Firebase Storage เลย** — รูปหลักฐาน/รูปเงินทอน/ลายเซ็น ถูกบีบอัดที่เครื่องผู้ใช้แล้วเก็บเป็น base64 ลง Firestore โดยตรง ทำให้ใช้แพ็กฟรี Spark ของ Firebase ได้ 100% โดยไม่ต้องผูกบัตรเครดิตเลย (ดูเหตุผลในหัวข้อ "เรื่อง Firebase Storage" ด้านล่าง)

> หมายเหตุ: นี่คือแนวป้องกันระดับพื้นฐาน-กลางที่ครอบคลุมสถานการณ์ทั่วไปของร้านค้า ถ้าธุรกิจมีความเสี่ยงสูงหรือเงินหมุนเวียนจำนวนมาก แนะนำให้ให้ผู้เชี่ยวชาญด้านความปลอดภัยตรวจสอบ `firestore.rules` อีกครั้งก่อนใช้งานจริง

## โครงสร้างระบบ

- **พนักงาน (staff)**: บันทึกรายการใหม่ (เลือกฝั่งเงินหมุนเวียนที่เกี่ยวข้อง), ดูและแก้ไขรายการของตัวเอง (เฉพาะตอนยังไม่ถูกตรวจสอบ), พิมพ์ใบเบิกของรายการตัวเองหลังอนุมัติแล้ว
- **เจ้าของ/ผู้จัดการ (owner)**: เห็นรายการของทุกคนทุกฝั่ง, อนุมัติ (พร้อมเซ็นชื่อออนไลน์) / ตีกลับ / ยกเลิกรายการ, แก้ไขข้อมูลย้อนหลังได้ (มีเหตุผล+ประวัติ), จัดการสิทธิ์ผู้ใช้งานในเมนู "ผู้ใช้งาน", ตั้งค่า/เติมเงินกองทุนในเมนู "กองทุน", ดูและพิมพ์รายงาน Statement ในเมนู "รายงาน", และเป็นคนเดียวที่เข้าโมดูล "โอนจ่าย" (บัญชีธนาคาร) ได้
- **ผู้อ่าน (guest)**: ดูรายการที่อนุมัติแล้วทั้งหมด + ยอดคงเหลือกองทุน + รายงาน Statement ได้อย่างเดียว กดอนุมัติ/แก้ไข/ลบ/บันทึกรายการใหม่ไม่ได้ และ **มองไม่เห็นโมดูล "โอนจ่าย" เลย** เหมาะสำหรับผู้ร่วมหุ้น/นักบัญชีที่แค่ต้องการติดตามตัวเลข
- ผู้สมัครใหม่ทุกคนจะอยู่ในสถานะ **"รออนุมัติ" (pending)** จนกว่าเจ้าของจะกำหนดสิทธิ์ให้ (เลือกได้ว่าจะเป็นพนักงาน / ผู้อ่าน / เจ้าของ)
- **ฝั่งเงินหมุนเวียน (Funds)**: ระบบรองรับได้หลายฝั่งไม่จำกัด เช่น "หน้าร้าน" และ "ออกส่งสินค้าและเบี้ยเลี้ยง" — เจ้าของเป็นผู้สร้างฝั่งและตั้งยอดตั้งต้น ทุกรายการรายรับ/รายจ่ายต้องระบุว่าเป็นของฝั่งไหน ยอดคงเหลือของแต่ละฝั่งคำนวณจาก ยอดตั้งต้น + เงินที่เติมเข้า + รายรับที่อนุมัติแล้ว − รายจ่ายที่อนุมัติแล้ว โดยอัตโนมัติแบบเรียลไทม์
- **เข้าสู่ระบบด้วยชื่อผู้ใช้ + PIN** (ไม่ใช่อีเมล/รหัสผ่าน) — ดูรายละเอียดในหัวข้อ "เรื่องการเข้าสู่ระบบด้วย PIN" ด้านล่าง

## ขั้นตอนที่ 1: สร้างโปรเจกต์ Firebase

1. ไปที่ https://console.firebase.google.com แล้วกด **สร้างโปรเจกต์ (Add project)**
2. ตั้งชื่อโปรเจกต์ เช่น `my-shop-cash-ledger` แล้วกดสร้างจนเสร็จ
3. ในเมนูซ้าย ไปที่ **Build > Authentication** กด **Get started** แล้วเปิดใช้งานผู้ให้บริการ **Email/Password**
4. ไปที่ **Build > Firestore Database** กด **Create database** เลือกโหมด **Production mode** และเลือก location ที่ใกล้ร้าน (เช่น `asia-southeast1`)
5. ไปที่ **Project settings (รูปเฟือง) > General** เลื่อนลงไปที่ "Your apps" กดไอคอน **</>** (Web) เพื่อสร้างเว็บแอป ตั้งชื่ออะไรก็ได้ แล้วคัดลอกค่า `firebaseConfig` ที่ได้ไว้ (จะใช้ในขั้นตอนที่ 3)

> **ไม่ต้องสร้าง Storage** — แอปนี้ไม่ใช้ Firebase Storage เลย (ดูรายละเอียดในหัวข้อ "เรื่อง Firebase Storage" ด้านล่างของไฟล์นี้) จึงอยู่ในแพ็กฟรี Spark ได้โดยไม่ต้องผูกบัตรเครดิต ข้าม Storage ไปได้เลย

## ขั้นตอนที่ 2: ตั้งค่ากฎความปลอดภัย (สำคัญมาก)

อัปโหลดกฎจากไฟล์ในโปรเจกต์นี้เพื่อให้ระบบป้องกันทุจริตทำงาน:

**วิธีที่ 1 — ผ่านหน้าเว็บ (ง่ายที่สุด)**
- ไปที่ **Firestore Database > Rules** คัดลอกเนื้อหาทั้งหมดจากไฟล์ `firestore.rules` ในโปรเจกต์นี้ไปวางแทนของเดิม แล้วกด **Publish**

**วิธีที่ 2 — ผ่าน Firebase CLI**
```bash
npm install -g firebase-tools
firebase login
firebase use --add   # เลือกโปรเจกต์ที่สร้างไว้
firebase deploy --only firestore:rules,firestore:indexes
```

## ขั้นตอนที่ 3: ตั้งค่าโปรเจกต์และรันบนเครื่องตัวเอง (ทดสอบก่อน deploy)

```bash
npm install
cp .env.example .env
```

เปิดไฟล์ `.env` แล้วใส่ค่าจาก `firebaseConfig` ที่คัดลอกไว้ในขั้นตอนที่ 1:

```
VITE_FIREBASE_API_KEY=...
VITE_FIREBASE_AUTH_DOMAIN=...
VITE_FIREBASE_PROJECT_ID=...
VITE_FIREBASE_MESSAGING_SENDER_ID=...
VITE_FIREBASE_APP_ID=...
```

รันทดสอบ:
```bash
npm run dev
```

## ขั้นตอนที่ 4: ตั้งบัญชีเจ้าของร้านคนแรก (ทำครั้งเดียว)

1. เปิดเว็บแอป กด **สมัครใช้งาน** ตั้งชื่อผู้ใช้ (username) และ PIN ของเจ้าของร้าน (บัญชีนี้จะอยู่ในสถานะ "รออนุมัติ")
2. กลับไปที่ Firebase Console > **Firestore Database > Data**
3. เปิด collection **users** จะเห็นเอกสารของบัญชีที่เพิ่งสมัคร
4. แก้ไขฟิลด์ `role` จาก `pending` เป็น `owner` แล้วบันทึก
5. กลับไปที่เว็บแอป รีเฟรชหน้า — ตอนนี้จะเข้าสู่ระบบในฐานะเจ้าของร้านได้แล้ว และสามารถไปที่เมนู **"ผู้ใช้งาน"** เพื่ออนุมัติพนักงาน/ผู้อ่านคนอื่นๆ ที่สมัครตามมาได้เอง (ไม่ต้องเข้า Firebase Console อีก)

## ขั้นตอนที่ 4.5: สร้างฝั่งเงินหมุนเวียน (ทำครั้งเดียว ก่อนให้พนักงานเริ่มบันทึก)

1. ในฐานะเจ้าของร้าน ไปที่เมนู **"กองทุน"**
2. กรอกแบบฟอร์ม "เพิ่มฝั่งเงินหมุนเวียนใหม่" สร้างฝั่งแรก: ชื่อ **หน้าร้าน** ยอดเงินตั้งต้น **30000**
3. สร้างฝั่งที่สอง: ชื่อ **ออกส่งสินค้าและเบี้ยเลี้ยง** ยอดเงินตั้งต้น **20000**
4. จะเห็นการ์ดของทั้งสองฝั่งพร้อมยอดคงเหลือปัจจุบัน และช่องสำหรับ **"เติมเงินเข้ากองทุน"** เมื่อเจ้าของนำเงินมาเติมเข้าฝั่งใดฝั่งหนึ่งภายหลัง (เช่น เติมเงินหมุนเวียนหน้าร้านกลับไป 30,000 ทุกสิ้นเดือน) — จำนวนที่กรอกจะถูกบวกเข้ายอดคงเหลือทันที พร้อมเก็บประวัติการเติมเงินไว้ให้ตรวจสอบย้อนหลัง

จากนั้นเมื่อพนักงานกด "+ บันทึกใหม่" จะมีให้เลือกฝั่งเงินหมุนเวียนก่อนกรอกรายการเสมอ

## ขั้นตอนที่ 5: ขึ้นเว็บจริงบน Netlify

**วิธีที่ 1 — ลากวางโฟลเดอร์ (เร็วที่สุด ไม่ต้องใช้ Git)**
```bash
npm run build
```
จากนั้นไปที่ https://app.netlify.com/drop แล้วลากโฟลเดอร์ `dist` ที่ได้ไปวาง — จะได้ลิงก์เว็บทันที (แต่ต้องตั้ง environment variables ก่อน build ทุกครั้ง วิธีนี้เหมาะกับทดสอบเร็วๆ)

**วิธีที่ 2 — เชื่อมกับ GitHub (ทำแล้ว แนะนำให้ใช้ เพราะจะมีการแก้ไข/เพิ่มฟีเจอร์ต่อเรื่อยๆ ในอนาคต)**

โปรเจกต์นี้ initialize git และ commit แรกไว้ให้แล้ว (ดูขั้นตอนใน "เชื่อมต่อ GitHub" ด้านล่าง) เหลือแค่สร้าง repo บน GitHub แล้ว push ขึ้นไป จากนั้นเชื่อม Netlify กับ repo นั้น — ทุกครั้งที่แก้โค้ดแล้ว push ใหม่ เว็บจะ deploy ให้อัตโนมัติ

## ขั้นตอนที่ 5.5: เชื่อมต่อ GitHub

**5.5.1 — สร้าง repo เปล่าบน GitHub**
1. ไปที่ https://github.com/new
2. ตั้งชื่อ repo เช่น `cash-ledger` เลือก **Private** (แนะนำ เพราะโค้ดมีโครงสร้างข้อมูลธุรกิจอยู่)
3. **ห้ามติ๊ก** "Add a README file" / .gitignore / license ใดๆ ทั้งสิ้น (ปล่อยเป็น repo เปล่า เพราะโปรเจกต์นี้มีไฟล์พวกนี้และมี git history ของตัวเองอยู่แล้ว) แล้วกด **Create repository**
4. หน้าที่ได้จะมีคำสั่งให้คัดลอก URL ของ repo ไว้ เช่น `https://github.com/<username>/cash-ledger.git`

**5.5.2 — Push โค้ดที่แตกไฟล์ไว้ขึ้น GitHub**

เปิด terminal ในโฟลเดอร์โปรเจกต์ที่แตกไฟล์ zip ออกมา (จะมีโฟลเดอร์ `.git` ซ่อนอยู่แล้วพร้อม commit แรกให้):
```bash
git remote add origin https://github.com/<username>/cash-ledger.git
git push -u origin main
```
ใส่ username/password (หรือ Personal Access Token ถ้า GitHub ขอ — ดูวิธีสร้างได้ที่ Settings > Developer settings > Personal access tokens) แล้ว push จะขึ้นไปพร้อม commit ประวัติเริ่มต้น

**5.5.3 — เชื่อม Netlify กับ repo นี้**
1. ที่ Netlify กด **Add new site > Import an existing project**
2. เลือก **GitHub** แล้วอนุญาตให้ Netlify เข้าถึง แล้วเลือก repo `cash-ledger`
3. Build command: `npm run build`, Publish directory: `dist` (ระบบจะอ่านจาก `netlify.toml` ให้อัตโนมัติอยู่แล้ว ไม่ต้องกรอกเองก็ได้)
4. ไปที่ **Site configuration > Environment variables** เพิ่มตัวแปรทั้ง 5 ตัวเดียวกับในไฟล์ `.env` ของคุณ (ค่าจาก Firebase Console ในขั้นตอนที่ 1)
5. กด **Deploy site**

จากนี้ไปทุกครั้งที่ต้องการแก้ไข/เพิ่มฟีเจอร์: แก้โค้ดในเครื่อง → `git add -A && git commit -m "อธิบายสิ่งที่แก้"` → `git push` → Netlify จะ build และขึ้นเว็บใหม่ให้อัตโนมัติภายในไม่กี่นาที ไม่ต้อง build/ลากอัปโหลดเองอีก

## ขั้นตอนที่ 6: อนุญาต Domain ของ Netlify ให้ Firebase Auth ทำงาน

1. คัดลอก URL เว็บที่ได้จาก Netlify (เช่น `your-shop.netlify.app`)
2. กลับไปที่ Firebase Console > **Authentication > Settings > Authorized domains** กด **Add domain** แล้ววาง domain นั้นลงไป

ถึงตรงนี้ระบบพร้อมใช้งานจริงแล้ว — เข้าผ่านมือถือเครื่องไหนก็ได้โดยเปิดลิงก์เดียวกันแล้วเข้าสู่ระบบด้วยบัญชีของตัวเอง

## วิธีใช้งานประจำวัน

- **พนักงาน**: กด "+ บันทึกใหม่" → เลือกฝั่งเงินหมุนเวียน (หน้าร้าน / ออกส่งสินค้าและเบี้ยเลี้ยง) → เลือกรายรับ/รายจ่าย → กรอกจำนวนเงิน/รายละเอียด/เงินทอน → แนบรูปหลักฐาน → บันทึก (รายการจะรอเจ้าของตรวจสอบ)
- **เจ้าของอนุมัติ**: เข้าเมนู "ตรวจสอบทั้งหมด" กรองตามสถานะ/พนักงาน/ฝั่ง แล้วกดเข้าไปดูรายละเอียดแต่ละรายการ → กด "อนุมัติ (เซ็นยืนยัน)" → **วาดลายเซ็นในกรอบที่ขึ้นมา** → ยืนยัน — รายการจะกลายเป็น "อนุมัติแล้ว" และถือว่า **เบิกสำเร็จ** ตั้งแต่วินาทีนั้น (ถ้ายังไม่เซ็น จะกดอนุมัติไม่ผ่าน)
- **พิมพ์ใบเบิก**: หลังอนุมัติแล้ว จะมีปุ่ม "พิมพ์ใบเบิก" ในหน้ารายละเอียดรายการ กดแล้วจะเปิดเอกสารพร้อมพิมพ์/บันทึกเป็น PDF มีลายเซ็นผู้อนุมัติแนบอยู่ในเอกสารด้วย
- **แก้ไขรายการ**: กดเข้ารายการ → "แก้ไขรายการ" → แก้ค่าที่ผิด → ใส่เหตุผล (บังคับ) → บันทึก ระบบจะเก็บ before/after ไว้ให้ตรวจสอบย้อนหลังได้เสมอ
- **เติมเงินเข้ากองทุน**: เจ้าของเข้าเมนู "กองทุน" กรอกจำนวนเงินในช่อง "เติมเงินเข้ากองทุน" ของฝั่งที่ต้องการ แล้วกด "เติมเงิน" ยอดคงเหลือของฝั่งนั้นจะปรับเพิ่มทันที
- **พิมพ์รายงาน Statement**: เจ้าของเข้าเมนู "รายงาน" เลือกฝั่งเงินหมุนเวียน แล้วเลือกช่วงวันที่เอง หรือกดปุ่มลัด "วันนี้ / เดือนนี้ / ปีนี้" ระบบจะแสดงยอดยกมา รายการเคลื่อนไหวทั้งหมดในช่วงนั้น (พร้อมยอดคงเหลือหลังแต่ละรายการ) และยอดคงเหลือปิดงวด กดปุ่ม "พิมพ์รายงาน" เพื่อพิมพ์หรือบันทึกเป็น PDF

## โมดูล "โอนจ่าย" (เงินโอนผ่านธนาคาร ไม่ใช่เงินสด — เฉพาะเจ้าของ/แอดมิน)

โมดูลนี้แยกต่างหากจากระบบเงินสด/กองทุนหมุนเวียนทั้งหมด ไม่มีขั้นตอนอนุมัติหรือเซ็นชื่อ และ **พนักงานมองไม่เห็นเมนูนี้เลย** — เข้าถึงได้เฉพาะบัญชีที่มี role เป็น owner เท่านั้น ใช้สำหรับบันทึกวงจรการเบิกเงินโอนเข้าบัญชี แล้วโอนจ่ายออกไปยังผู้รับปลายทาง โดยตัดยอดกันเองอัตโนมัติ

**แนวคิดของระบบ**
- **บัญชี A** = บัญชีธนาคารของเรา ใช้รับเงินตอนเบิก และเป็นบัญชีต้นทางตอนโอนจ่ายออก
- **บัญชี B** = บัญชีปลายทางของผู้รับโอน (ซัพพลายเออร์ พนักงาน ฯลฯ)
- **ใบเบิกเงินโอน**: รายการของสิ่งที่ต้องจ่าย (หมวดหมู่ + รายละเอียด + ยอดเงิน หลายบรรทัด) รวมเป็นยอดที่ "เบิกเข้า" บัญชี A
- **ใบโอนจ่าย**: บันทึกการโอนเงินจริงจากบัญชี A ไปยังบัญชี B แต่ละใบเลือกได้ว่าจะ "ตัดยอด" กับใบเบิกใบไหน — ตัดได้หลายครั้งจนกว่าจะครบยอดของใบเบิกนั้น (ระบบคำนวณ "ยอดคงเหลือ" ของแต่ละใบเบิกให้อัตโนมัติจากผลรวมใบโอนจ่ายที่ผูกไว้)

**วิธีใช้งาน**
1. เมนู **"โอนจ่าย" > "บัญชีธนาคาร & หมวดหมู่"**: บันทึกบัญชี A (บัญชีของเรา) และบัญชี B (บัญชีผู้รับโอน) ไว้เป็นรายการโปรดก่อนใช้งานครั้งแรก พร้อมตั้งหมวดหมู่รายจ่ายที่ใช้บ่อย (เช่น ค่าน้ำมัน, เบี้ยเลี้ยง)
2. แท็บ **"ใบเบิกเงินโอน"** กด "+ สร้างใบเบิกใหม่" → เลือกบัญชี A ที่จะรับเงินเข้า + วันที่เบิก (กรอกครั้งเดียว) → เพิ่มบรรทัดรายการได้ไม่จำกัด (หมวดหมู่/รายละเอียด/ยอดเงิน แต่ละบรรทัดมีเลขลำดับอัตโนมัติ) → กดบันทึกทีเดียวทั้งใบ ระบบจะออกเลขที่ใบเบิกอัตโนมัติ (เช่น WR-0001) กลับมาแก้ไข เพิ่ม ลบบรรทัด หรือลบทั้งใบได้ตลอด และพิมพ์/บันทึกเป็น PDF ได้จากปุ่ม "พิมพ์ / PDF"
3. แท็บ **"ใบโอนจ่าย"** กด "+ สร้างใบโอนจ่ายใหม่" → เลือกบัญชี A ต้นทาง → เลือกใบเบิกที่จะตัดยอดด้วย (ระบบจะโชว์ยอดคงเหลือของใบเบิกนั้นให้ดูก่อนบันทึก) → เพิ่มบรรทัดการโอน (วันที่โอน/บัญชีผู้รับโอน B/ยอดเงิน/หมายเหตุ) หลายรายการได้ในครั้งเดียว → กดบันทึก ระบบออกเลขที่ใบโอนจ่ายอัตโนมัติ (เช่น TP-0001) ถ้ายอดรวมเกินยอดคงเหลือของใบเบิก ระบบจะเตือนไว้ให้ตรวจสอบ (ไม่ได้บล็อกการบันทึก เผื่อกรณีมีเหตุผลพิเศษ) แก้ไข/ลบ/พิมพ์ PDF ได้เช่นเดียวกับใบเบิก
4. หน้ารายการ "ใบเบิกเงินโอน" จะโชว์สถานะ "ตัดยอดครบแล้ว" หรือ "คงเหลือ X บาท" ของแต่ละใบให้เห็นทันทีว่าใบไหนยังจ่ายไม่ครบ

## เรื่องการเข้าสู่ระบบด้วย PIN

ระบบล็อกอินด้วย **ชื่อผู้ใช้ + PIN ตัวเลข 4-6 หลัก** แทนอีเมล/รหัสผ่าน เพื่อให้พนักงานจำและพิมพ์ง่ายขึ้น โดยเบื้องหลังยังใช้ Firebase Authentication แบบ email/password เดิม (ฟรี ไม่ต้องใช้ Cloud Functions ซึ่งต้องอัปเกรดเป็น Blaze) เพียงแต่แปลงค่าให้อัตโนมัติ:

- **ชื่อผู้ใช้** → ถูกแปลงเป็นอีเมลปลอมรูปแบบ `<username>@pin.local` ที่ไม่มีการส่งเมลจริง ใช้เป็นตัวระบุบัญชีใน Firebase Auth เท่านั้น ต้องไม่ซ้ำกันทั้งระบบ (สมัครซ้ำชื่อจะขึ้น error "ชื่อผู้ใช้นี้ถูกใช้งานแล้ว")
- **PIN** → ถ้าใส่ 4-5 หลัก ระบบจะเติมเลข 0 ข้างหน้าให้ครบ 6 หลักโดยอัตโนมัติก่อนส่งเข้า Firebase (Firebase บังคับรหัสผ่านอย่างน้อย 6 ตัวอักษร) ผู้ใช้ไม่ต้องรู้เรื่องนี้ แค่จำ PIN ที่ตัวเองตั้งไว้แล้วพิมพ์ให้ตรงทุกครั้งก็พอ

**ผลกระทบกับบัญชีเจ้าของที่สมัครไว้ก่อนหน้านี้ด้วยอีเมลจริง**: บัญชีเก่าจะใช้ล็อกอินผ่านหน้าเว็บใหม่ไม่ได้แล้ว (เพราะฟอร์มเปลี่ยนไปถามชื่อผู้ใช้แทนอีเมล) ให้ **สมัครบัญชีใหม่ผ่านระบบ PIN** แล้วไปตั้ง `role` เป็น `owner` ในหน้า Firestore Console อีกครั้งตามขั้นตอนที่ 4 (ทำครั้งเดียว ไม่ยุ่งยาก)

## เรื่องบทบาท "ผู้อ่าน (Guest)"

เพิ่มบทบาทที่ 3 นอกจากพนักงานกับเจ้าของ — เหมาะสำหรับคนที่แค่อยากติดตามตัวเลข (เช่น ผู้ร่วมหุ้น นักบัญชีภายนอก) โดยไม่ต้องให้สิทธิ์บันทึก/แก้ไขอะไร:

- เห็นได้: รายการที่ **อนุมัติแล้ว** ทั้งหมดทุกฝั่ง, ยอดคงเหลือกองทุนแบบเรียลไทม์, หน้ารายงาน Statement (พิมพ์ได้ด้วย)
- เห็นไม่ได้/ทำไม่ได้: บันทึกรายการใหม่, แก้ไข/อนุมัติ/ตีกลับรายการใดๆ, หน้าจัดการผู้ใช้งาน, หน้าตั้งค่ากองทุน, และ **โมดูล "โอนจ่าย" ทั้งหมด** (ไม่เห็นเมนูเลย)
- วิธีตั้งค่า: ให้คนนั้นไปสมัครสมาชิกตามปกติ (จะอยู่ในสถานะ "รออนุมัติ") แล้วเจ้าของเข้าเมนู **"ผู้ใช้งาน"** กดปุ่ม **"ตั้งเป็นผู้อ่าน"** ให้

## หมายเหตุเรื่องค่าใช้จ่าย

Firebase มี free tier (Spark plan) ที่เพียงพอสำหรับร้านค้าขนาดเล็ก-กลางในการใช้งานปกติ (Firestore/Auth มีโควตาฟรีรายวัน) และแอปนี้ไม่ใช้ Firebase Storage เลย (ดูหัวข้อถัดไป) จึงไม่ต้องผูกบัตรเครดิตอะไรทั้งสิ้น Netlify ก็มี free tier สำหรับเว็บสถิตเช่นนี้เช่นกัน ถ้าปริมาณรายการเยอะมากในระยะยาวจนเกินโควตาฟรีของ Firestore ควรตรวจสอบราคาปัจจุบันที่หน้า pricing ของทั้งสองบริการ

## เรื่อง Firebase Storage

**แอปนี้ไม่ใช้ Firebase Storage เลย** เพราะตั้งแต่ 3 กุมภาพันธ์ 2026 เป็นต้นมา Google กำหนดให้ Firebase Storage ต้องอัปเกรดโปรเจกต์เป็นแพ็ก **Blaze (pay-as-you-go)** เท่านั้นถึงจะใช้ได้ — แม้จะใช้ไม่เกินโควตาฟรีก็ต้องผูกบัตรเครดิตไว้กับโปรเจกต์อยู่ดี (จะไม่ถูกเรียกเก็บเงินถ้าไม่เกินโควตา แต่หลายคนไม่สะดวกผูกบัตร)

เพื่อให้ใช้แพ็กฟรี **Spark** ได้ 100% โดยไม่ต้องผูกบัตรอะไรเลย แอปนี้จึงออกแบบให้:
- รูปหลักฐาน/รูปเงินทอน/ลายเซ็นอนุมัติ ถูก**บีบอัดที่เครื่องผู้ใช้ก่อนอัปโหลด** (ย่อขนาดรูป + ลดคุณภาพ JPEG อัตโนมัติจนเหลือประมาณ 100-180 KB ต่อรูป) แล้วเก็บเป็นข้อความ base64 ฝังลงในเอกสาร Firestore โดยตรง แทนที่จะอัปโหลดไปเก็บที่ Storage
- ตอนแนบรูปในฟอร์มบันทึกรายการ จะเห็นข้อความ "บีบอัดแล้วเหลือ ~XX KB" ให้ตรวจสอบก่อนบันทึกเสมอ
- ข้อจำกัด: Firestore จำกัดขนาดเอกสารแต่ละอันไว้ที่ 1 MB ระบบบีบอัดไว้ให้อยู่ในขอบเขตที่ปลอดภัยแล้ว แต่ถ้ารูปต้นฉบับซับซ้อนมากเป็นพิเศษ (เช่น รูปความละเอียดสูงมากที่ยังบีบไม่ลงหลังพยายามหลายรอบ) อาจต้องถ่ายรูปใหม่ให้เรียบง่ายขึ้นเล็กน้อย

ถ้าในอนาคตอยากได้คุณภาพรูปที่สูงขึ้นและไม่ติดข้อจำกัดขนาดเอกสาร สามารถอัปเกรดเป็น Blaze แล้วขอให้ปรับโค้ดกลับไปใช้ Firebase Storage แทนได้ (Blaze ยังฟรีอยู่ถ้าไม่เกินโควตา แค่ต้องผูกบัตรไว้เฉยๆ)

## เรื่อง GitHub

โปรเจกต์นี้เชื่อมต่อ GitHub ให้แล้วตามขั้นตอนที่ 5.5 ด้านบน (git init + commit แรกไว้ในไฟล์ zip นี้เรียบร้อย เหลือแค่ push ขึ้น repo ที่สร้างใหม่) เพราะจะมีการแก้ไข/เพิ่มฟีเจอร์กันต่อเรื่อยๆ — วิธีนี้ทำให้ทุกครั้งที่แก้โค้ด แค่ `git push` เว็บก็ deploy ให้อัตโนมัติ ไม่ต้อง build/ลากอัปโหลดเองทุกรอบ และมีประวัติการแก้ไขเก็บไว้ย้อนดูได้ด้วย
